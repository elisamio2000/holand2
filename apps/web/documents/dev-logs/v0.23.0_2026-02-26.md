## Technical Patterns Used

### 1. Sub-component Pattern
For standalone utility functions that return translatable strings (e.g. `getStepLabel` in thinking-steps.tsx), added `t` as an explicit parameter:

```typescript
// Before
function getStepLabel(step: ThinkingStep): string {
  if (step.type === 'thinking') return step.isActive ? 'Thinkingâ€¦' : 'Analyzed';
  ...
}

// After  
function getStepLabel(step: ThinkingStep, t: (key: string) => string): string {
  if (step.type === 'thinking')
    return step.isActive ? t('thinkingSteps.thinkingActive') : t('thinkingSteps.thinkingDone');
  ...
}
// Called with: getStepLabel(step, t)  [t from useTranslation() in the calling component]
```

### 2. Config Object with `labelKey` Pattern
For module-level config objects with display labels (NODE_CONFIG in trace-panel.tsx, TABS in roles-permissions-view.tsx), replaced `label: string` with `labelKey: string` pointing to translation keys:

```typescript
// Before
const NODE_CONFIG = {
  assess_complexity: { label: 'Assessment', ... },
}

// After
const NODE_CONFIG = {
  assess_complexity: { labelKey: 'tracePanel.nodes.assessment', ... },
}
// Used with: t(config.labelKey)  [t from useTranslation() in sub-component]
```

### 3. Dynamic Options Inside Component
For EXPIRY_OPTIONS in share-session-modal.tsx, labels that vary by language are computed inside the component:

```tsx
const expiryLabels: Record<number, string> = {
  1: t('shareModal.expiry1h'),
  24: t('shareModal.expiry24h'),
  ...
};
// Render: {expiryLabels[opt.value]}
```

### 4. Sub-components Needing `useTranslation`
Each React function component (even those nested in the same file) got its own `const { t } = useTranslation()` if they rendered translatable text:
- `SessionStatsTable` in admin-stats.tsx
- `StepBadge`, `StepDetail`, `ToolDetail` in trace-panel.tsx
- `SummaryView`, `TimelineStep` in thinking-steps.tsx
- `RbacConfigSection`, `RoutePermissionsSection` in permissions-management.tsx
