## 1) خواسته‌های قطعی محصول (Scope Baseline)

### RQ-01: QA کامل صفحه به صفحه
- شرح: همه صفحات باید بازبینی شوند و ایرادها رفع شوند.
- معیار پذیرش:
  - هیچ صفحه بحرانی با خطای بلاک‌کننده باقی نماند.
  - مسیرهای اصلی کاربر (ورود، آزمون، گزارش، پنل) پایدار باشند.

### RQ-02: یکپارچگی کامل برند هالند
- شرح: حذف کامل آثار قالب/برند قدیمی و استفاده از برند هالند در همه نقاط.
- شامل:
  - favicon
  - logo
  - icon
  - avatar
  - tooltip/labels
  - i18n keys و namespace hygiene
  - حذف ردپای نام‌ها/کلیدهای legacy مثل nativeAiChat و مشابه
- معیار پذیرش:
  - هیچ مورد قابل مشاهده از برند/نام قدیمی در UI و تنظیمات باقی نماند.

### RQ-03: رفع خروج ناخواسته از حساب در صفحات کلیدی
- شرح: مسیرهای زیر نباید کاربر را ناخواسته Sign-out کنند:
  - /career-guidance/reports
  - /career-guidance/expert-lab
- معیار پذیرش:
  - در خطاهای API (خصوصا 401/403) نشست کاربر بی‌جهت حذف نشود.
  - صفحه با خطای درون‌صفحه‌ای قابل فهم degrade شود.

### RQ-04: جریان کاربری کامل آزمون تا گزارش
- شرح: کاربر باید بتواند آزمون دهد، نتیجه بگیرد، و گزارش قابل استفاده دریافت کند.
- معیار پذیرش:
  - پایان جریان بدون شکست session
  - گزارش قابل خواندن + پیشنهاد/تفسیر عملیاتی

### RQ-05: افزایش سرعت ثبت پاسخ و نمایش نتیجه
- شرح: ثبت پاسخ‌ها و نمایش نتیجه آزمون نباید کند و آزاردهنده باشد.
- معیار پذیرش:
  - تعامل پاسخ‌دهی کاربر بدون مکث محسوس انجام شود.
  - زمان تکمیل آزمون تا نمایش نتیجه اولیه کاهش یابد.
  - ارسال پاسخ‌ها به‌صورت مقاوم در برابر قطعی موقت شبکه انجام شود.

### RQ-06: طراحی روش ترکیبی برای هدایت تحصیلی/شغلی نوجوان
- شرح: ترکیب معتبر آزمون‌ها برای شخصیت‌شناسی، استعداد، توانایی، نقاط قوت/ضعف دانش‌آموزان.
- معیار پذیرش:
  - خروجی تصمیم‌یار بر اساس چند منبع (نه یک آزمون واحد) تولید شود.
  - گزارش ترکیبی شامل مسیر مدرسه/دانشگاه + اقدام مهارتی باشد.
  - محدودیت‌های علمی و غیرقطعی بودن نتیجه به‌صراحت بیان شود.

### RQ-07: بازطراحی تجربه سوال‌دهی برای کودک/نوجوان
- شرح: شیوه آزمون‌دهی و متن سوالات برای رده سنی پایین‌تر ساده‌تر و قابل‌فهم‌تر شود.
- معیار پذیرش:
  - کاهش خستگی و افزایش تکمیل آزمون.
  - حفظ کیفیت پاسخ و پایایی داده.

- Done definition:
  - هیچ trace از نام/برند قدیمی در UI/runtime باقی نماند.

### Epic B: Session-Safe UX
- B1: استاندارد خطای 401/403 در کل صفحات protected
- B2: جلوگیری از logout زنجیره‌ای در حالت dev bypass/edge cases

- Done definition:

### Epic C: AI Admin Foundation
- C1: DB schema برای provider/model/pipeline/profile
- C2: CRUD ادمین برای تنظیم provider/model
- C3: endpoints discovery برای vLLM/Ollama
- C4: تست امنیت role/permission در دسترسی ادمین
- Done definition:
  - ادمین بتواند provider را ثبت/اعتبارسنجی/کشف مدل/ذخیره کند.

### Epic D: AI Report Pipeline
- D1: endpoint تولید گزارش AI از داده session/result
- D2: prompt templates + guardrails + fallback policy
- D3: نمایش structured AI insights در گزارش
- D4: quality metrics و feedback loop
- Done definition:
  - گزارش هوشمند با کیفیت پایدار در محیط عملیاتی ارائه شود.

### Epic E: Performance Acceleration
- E1: batch + debounce در sync پاسخ‌ها و flush قطعی قبل از complete
- E2: حذف round-tripهای غیرضروری در مرحله اتمام آزمون و fetch نتیجه
- E3: تعریف و مانیتور شاخص‌های latency (p50/p95) برای submit/result
- Done definition:
  - کاربر در پاسخ‌دهی و دیدن نتیجه با تاخیر آزاردهنده مواجه نشود.

### Epic F: Teen-Focused Interpretation Quality
- F1: استخراج taxonomy مفهومی از منابع خریداری‌شده (هدایت تحصیلی نوجوان)
- F2: تنظیم prompt/template و rule-based layers بر اساس نوجوان
- F3: بنچمارک خروجی با Esanj و ثبت شکاف‌ها
- Done definition:
  - خروجی تحلیل برای رده 13-17 از نظر زبان، پیشنهادها و احتیاط علمی دقیق و قابل دفاع باشد.

### Epic G: Composite Assessment Model

- G2: جداسازی لایه تصمیم‌ساز از لایه اکتشافی (MBTI/MII)
- G3: قرارداد خروجی ترکیبی برای هدایت تحصیلی/شغلی
- Done definition:
  - گزارش نهایی با اتکا به مدل ترکیبی و قابل توضیح تولید شود.
