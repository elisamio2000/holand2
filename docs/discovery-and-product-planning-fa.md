# سند Discovery و برنامه ریزی محصول

## 1) بازتنظیم مسیر پروژه

این پروژه از این نقطه به بعد با رویکرد زیر جلو می رود:

1. ایده پردازی و تعریف مسئله
2. تحلیل نمونه های برتر بازار
3. استخراج فهرست قابلیت های مرجع
4. مقایسه با ایده محصول خودمان
5. شناسایی گزینه های رایگان و اوپن سورس
6. برنامه بهره برداری از نمونه های موجود
7. مستندسازی
8. شروع توسعه

## 2) ایده مرکزی محصول

یک وب اپلیکیشن چندسکویی برای هدایت تحصیلی و شغلی که:

- آزمون هالند (RIASEC) و MBTI را اجرا می کند
- نتیجه را صرفا به تیپ خلاصه نمی کند و خروجی قابل اقدام می دهد
- مسیر تحصیلی، شغلی و مهارتی مرحله ای پیشنهاد می دهد
- برای گروه های سنی مختلف، تجربه کاربری مناسب ارائه می دهد

## 3) تحلیل نمونه های مرجع بازار (خلاصه تحقیق)

### 3.1 Truity (Holland)

الگوهای مهم:

- اجرای آزمون مرحله ای
- تاکید بر ساده بودن پاسخ دهی
- تفسیر RIASEC با زبان قابل فهم
- نگاشت مستقیم تیپ به مشاغل
- تاکید بر اینکه آزمون تصمیم نهایی نیست

نکته قابل برداشت:

- باید در گزارش خودمان هم "توصیه گر" باشیم نه "حکم قطعی"

### 3.2 CareerExplorer

الگوهای مهم:

- مدل چندبعدی برای پیشنهاد (علاقه + شخصیت + سابقه + محیط)
- گزارش پیشرونده در حین آزمون
- قابلیت ذخیره و ادامه بعدی
- بانک بزرگ مشاغل/رشته ها
- شفافیت درباره داده و اعتبار مدل

نکته قابل برداشت:

- خروجی نهایی باید چندبعدی باشد، نه فقط MBTI یا RIASEC خام

### 3.3 OOH (BLS)

الگوهای مهم:

- اتصال پیشنهاد به داده های واقعی شغل (رشد، درآمد، تحصیلات)
- دسته بندی استاندارد مشاغل

نکته قابل برداشت:

- موتور پیشنهاد باید Data Layer بازار کار داشته باشد (نسخه MVP با دیتاست ساده)

## 4) قابلیت های برتر که باید در محصول داشته باشیم

### 4.1 هسته ارزیابی

- اجرای گام به گام آزمون هالند و MBTI
- ذخیره پیشرفت آزمون
- نمره دهی نسخه بندی شده
- شاخص اطمینان نتیجه در هر بعد

### 4.2 گزارش حرفه ای کاربر

- پروفایل ترکیبی (RIASEC + MBTI)
- توضیح نقاط قوت/ریسک
- پیشنهاد مشاغل با امتیاز تطابق
- پیشنهاد رشته/گرایش با دلیل
- برنامه رشد مهارتی 3/6/12 ماهه
- تحلیل قابل اقدام بر اساس نتیجه آزمون ها در نسخه اولیه (MVP)

### 4.3 بخش مشاور

- مشاهده نتایج مراجع
- مقایسه دوره ای (تغییرات)
- یادداشت و پلن مشترک

### 4.4 پنل تحلیل گر خبره (الزام جدید)

- ویرایش سوالات، گزینه ها، اوزان و فرمول های نمره گذاری
- نسخه بندی کامل و غیرقابل تغییر برای نسخه های منتشرشده
- شبیه سازی خروجی قبل از انتشار (Sandbox)
- جریان تایید چندمرحله ای (تحلیل گر، بازبین، منتشرکننده)
- امکان بازگشت سریع به نسخه قبلی (Rollback)
- گزارش اثر تغییرات بر خروجی های تاریخی (Impact Analysis)

### 4.5 هوشمندی و تحلیل

- دلیل قابل فهم برای هر پیشنهاد
- بازخورد کاربر روی پیشنهادها (مفید/نامفید)
- بهبود دوره ای مدل پیشنهاد با داده بازخورد

## 5) مقایسه ایده ما با نمونه های موجود

## Backend

- سرویس ها: Auth, Assessment, Recommendation, Reporting

## Database (تصمیم مصوب)

### فاز MVP: PostgreSQL

- دلیل: روابط قوی برای آزمون، پاسخ، نسخه سوال، گزارش
- گزارش گیری تحلیلی بهتر در شروع

### فاز Scale یا نیاز Document سنگین: MongoDB

- برای Event Log، رفتار کاربر، و داده نیمه ساختاریافته
- الگوی هیبریدی: Postgres (Core) + Mongo (Behavior)

## 8) طراحی UX برای گروه های سنی مختلف

- یک سیستم دیزاین واحد با Tokenهای پویا

- متن کوتاه و انگیزشی

## گروه سنی 30+

- مینیمال حرفه ای
- تحلیل عمیق، نمودارهای دقیق
- تمرکز بر تغییر شغل و ارتقای مسیر

## 10) فهرست قابلیت های MVP (اولویت بندی)

## Must-have

- ثبت نام/ورود

- ذخیره پاسخ و ادامه آزمون
- گزارش اولیه ترکیبی
- تحلیل کاربردی نتایج آزمون ها (الزامی در MVP)
- پیشنهاد اولیه مشاغل/رشته ها
- پروفایل سنی و Theme تطبیقی
- پنل نسخه بندی سوال/فرمول/معادله با نقش بندی کارشناسی

## Should-have

- داشبورد مشاور پایه
- خروجی PDF
- مقایسه دو نوبت آزمون

## Could-have

- موتور بازخورد و بهبود مدل
- اتصال API بازار کار

## 11) برنامه اجرایی Discovery تا Development

## مرحله A: Discovery (1 تا 2 هفته)

- تکمیل Benchmark رقبا
- تعریف PRD نسخه 1
- تعریف KPI محصول
- تعریف معیارهای علمی/اخلاقی آزمون

## مرحله B: Design (1 تا 2 هفته)

- Design System
- User Flow برای هر گروه سنی
- Wireframe + Prototype

## مرحله C: Build MVP (4 تا 6 هفته)

- Frontend: Next.js + TS + shadcn + Tailwind
- Backend: FastAPI
- DB: PostgreSQL
- استقرار اولیه + مانیتورینگ

## مرحله D: Validation (2 هفته)

- تست کاربردپذیری برای 4 گروه سنی
- بررسی کیفیت پیشنهادها
- اصلاح Rule Engine و UX

## 12) ریسک ها و کنترل

- ریسک: تفسیر بیش از حد قطعی نتیجه آزمون
- کنترل: زبان غیرقطعی + توضیح محدودیت

- ریسک: داده بازار کار ضعیف
- کنترل: شروع با دیتاست معتبر و نسخه بندی منبع داده

- ریسک: افت تکمیل آزمون
- کنترل: آزمون ماژولار + ذخیره خودکار + زمان تخمینی واضح
